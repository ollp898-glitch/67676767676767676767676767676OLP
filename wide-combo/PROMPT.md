# Wide Combo — инструкция для анализа

Это инструкция по чтению данных, а не источник прогнозов. Не подменяй недоступный файл поисковой выдачей и не придумывай вероятность, цену, итог или ссылку.

1. Открой [CHAT-START.md на GitHub](https://github.com/ollp898-glitch/67676767676767676767676767676OLP/blob/data/CHAT-START.md) или [raw CHAT-START.md](https://raw.githubusercontent.com/ollp898-glitch/67676767676767676767676767676OLP/data/CHAT-START.md).
2. Затем открой [candidates.csv на GitHub](https://github.com/ollp898-glitch/67676767676767676767676767676OLP/blob/data/wide-combo/candidates.csv) или [raw candidates.csv](https://raw.githubusercontent.com/ollp898-glitch/67676767676767676767676767676OLP/data/wide-combo/candidates.csv). Если файла нет, используй [slim.csv на GitHub](https://github.com/ollp898-glitch/67676767676767676767676767676OLP/blob/data/wide-combo/slim.csv) или [raw slim.csv](https://raw.githubusercontent.com/ollp898-glitch/67676767676767676767676767676OLP/data/wide-combo/slim.csv).
3. Если не открылись ни обычная, ни raw ссылка нужного файла, остановись и укажи обе точные ссылки и текст ошибки. Не объединяй строки разных снимков. Заголовки CSV `snapshot_at`, `snapshot_id`, `source_sha256` должны совпадать с исходным индексом.
4. Первая строка ответа: `snapshot_id`, `snapshot_at`, `source_sha256` из заголовка CSV. Ответ без неё недействителен.
5. Для оценки этапа 1 приведи самостоятельный источник и его ссылку для каждого исхода. Пока адаптера модели нет, `model_p` пустой: это не ошибка сканера и не разрешение выдумать прогноз. Если оценку подтвердить нельзя, отклони исход с причиной.
6. Этапы 2 (статистика) и 3 (мнения) выполняй только для исходов, прошедших этап 1, максимум 20 исходов за один заход. Каждое утверждение сопровождай ссылкой. Если данных для этапа нет, отклони исход; отсутствие данных не заменяй нулём.
7. Не выбирай два исхода одного `match_num`. Условия для всего комбо: `M = произведение (p_i / c_i) >= 1.05`, где `p_i` — меньшая из подтверждённых оценок этапов 1 и 2, а `c_i` — `best_ask` из CSV. Если модели нет, этап 1 должен дать подтверждённую ссылками оценку. При недостаточном M выдай промежуточный результат и число непроверенных номеров.
8. Итоговый расчётный кэф одиночных цен: `1 / произведение best_ask`. Это не фактическая котировка Combo RFQ. Не используй букмекерские цены Combo 2.0. Перед ставкой обнови цены выбранных ног и проверь фактическую котировку отдельно.

Ответ дай JSON с `snapshot_id`, `snapshot_at`, `source_sha256`, `status` (`final` или `intermediate`), `legs`, `rejected`, `not_checked`. В `legs` укажи только номера `W...` из CSV, `stage1_probability`, при наличии `stage2_probability`, `sources` и короткую `note`. В `rejected` укажи `{num,reason}`. В `not_checked` допускаются номера и диапазоны вроде `W101-W140`. Числа `best_ask` и кэф не считай достоверными из текста ответа: локальная команда `node wide-combo/log/validate-answer.js ANSWER.json SNAPSHOT_DIR` берёт их из CSV и пересчитывает сама.
